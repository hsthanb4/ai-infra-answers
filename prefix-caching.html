推理与选型

前缀缓存能省多少计算？什么请求适合 Prefix Caching

前缀缓存复用已处理的相同 token 前缀对应的 KV 状态，主要减少重复的 Prefill 计算。它不能让任意相似文本自动命中，也不会免掉后续新 token 的生成计算。

怎么判断自己的情况

适合反复携带同一长文档、固定说明或重复对话前缀的请求。前缀前部发生变化，可能影响后续共享范围；缓存也会受到内存容量、驱逐策略和请求隔离方式影响。不能把热缓存基准的加速直接当成全量线上收益。

一个具体例子

十次请求都读取同一份长合同、只更换末尾问题，可能有较大复用空间；十篇内容完全不同的文档，即使问题相同也未必能复用长前缀。

最小验证步骤

  1. 明确哪些 token 前缀在实际业务中完全一致。
  2. 分别测首次冷请求、重复热请求和真实混合流量。
  3. 记录命中比例、首字延迟与缓存占用，并检查不同用户之间的缓存隔离要求。
