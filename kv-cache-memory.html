KV Cache 显存怎么算？GQA、上下文和并发分别影响什么

普通自回归 Transformer 的 KV 张量可按 2 × 层数 × KV 头数 × 每头维度 × token 总数 × 每元素字节数估算。这里用 KV 头数，不是直接用 Query 头数；共享前缀和特殊注意力架构需要另算。

怎么判断自己的情况

GQA（分组查询注意力）让多个 Query 头共享一组 Key 和 Value，因此缓存大小取决于 KV 头数。token 总数要覆盖同时驻留的序列及已经生成的内容。分页管理还会引入块粒度、元数据和预留容量；多卡切分则要按引擎实际布局核算。

一个具体例子

假设 32 层、8 个 KV 头、每头 128 维、BF16 缓存，一条 4096 token 序列的原始 KV 张量约为 512 MiB。这是给定假设下的算术结果，不是任意 7B 模型的实测值。

最小验证步骤

  1. 从模型配置读取层数、KV 头数和头维度，确认是否为普通 KV 架构。
  2. 用实际缓存 dtype 和驻留 token 数计算，再检查引擎分块与分片。
  3. 用引擎日志及显存监控对照，区分已预分配缓存池和正在使用的缓存。
